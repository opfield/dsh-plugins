# MCP Hub для DeepSeek Harness

[English](README.md)

Плагин `@opfield/dsh-mcp-hub` для DeepSeek Harness (DSH): один хаб для всех MCP-серверов вместо отдельной записи `dsh-mcp-client` на каждый.

- **Режим на сервер.** `eager` — полные схемы инструментов, `lazy` — компактный каталог, `auto` — выбор по размеру. Серверы на сотни инструментов не съедают контекст.
- **HTTP напрямую, с OAuth.** Без `mcp-remote` и лишних процессов: кнопка Sign in, токены обновляются сами.
- **stdio без `npx`.** Пакет из кеша `npx` запускается как `node <bin>`, без процесса `npm exec` рядом с каждым сервером. Обновления `@latest` проверяются в фоне.
- **Страница настроек** в Plugins → MCP Hub: статус, режимы, добавление и правка серверов, вход. Всё применяется без перезапуска.
- **API для других плагинов.** Плагин может добавить в хаб свои серверы и пользоваться их сессиями; на странице хаба они показаны отдельной группой с его названием.

Сборки не требует: это обычные JS-файлы. Использует MCP SDK, который уже есть внутри DSH.

## Установка

1. **Установи плагин:** **Plugins → Add plugin**, введи `@opfield/dsh-mcp-hub` (или `github:opfield/dsh-plugins#path:/packages/mcp-hub`, чтобы поставить с GitHub), затем **Enable now**.
2. **Перенеси свои MCP-серверы** (если они уже настроены через `dsh-mcp-client`). Закрой DSH и запусти миграцию встроенным в DSH Node (скрипту нужен `yaml` из установки DSH):
   ```sh
   DSH="/Applications/DeepSeek Harness.app/Contents/MacOS/DeepSeek Harness"
   HUB=~/.dsh/profiles/desktop/node_modules/@opfield/dsh-mcp-hub
   ELECTRON_RUN_AS_NODE=1 "$DSH" "$HUB/scripts/migrate.mjs" ~/.dsh/profiles/desktop --dry-run   # что будет перенесено
   ELECTRON_RUN_AS_NODE=1 "$DSH" "$HUB/scripts/migrate.mjs" ~/.dsh/profiles/desktop
   ```
   `desktop` — профиль приложения по умолчанию.
   Скрипт убирает записи `@deepseek-ai/dsh-mcp-client` из `cordis.patch.yml` и переносит их в хаб. Обёртки распознаются: `npx mcp-remote <url>` становится прямым HTTP-сервером, `mcp-lazy … -- <команда>` — сервером в режиме `lazy`. Бэкап — `cordis.patch.yml.bak-before-mcp-hub`. Без миграции серверы можно просто добавить на странице настроек.
3. **Запусти DSH** и открой **Plugins → MCP Hub**. У HTTP-серверов с OAuth нажми **Sign in**, если хаб не подхватил токены `mcp-remote` сам.

DSH пока не обновляет плагины сам: чтобы обновить, удали плагин и добавь новую версию.

## Режимы

| Режим | Что видит модель |
|---|---|
| `eager` | Все инструменты как обычно: `mcp__<server>__<tool>` с полными схемами. |
| `lazy` | Инструменты не грузятся. Каждый сервер — строки «tool: краткое описание» внутри описания `mcp_call`. Схему модель получает через `mcp_describe(server, tool)`; вызов с неверными аргументами возвращает схему в ошибке. |
| `auto` | `eager`, если схемы сервера помещаются в порог (по умолчанию 2500 токенов), иначе `lazy`. |

Каталог меняется только при изменении набора инструментов, поэтому префикс запроса остаётся кешируемым.

## Как работают серверы

- **stdio** — команда, аргументы, env, рабочая папка. Значение `$cred:NAME` в env или заголовках берёт секрет из хранилища ключей DSH.
- **`npx <пакет>`** — если пакет уже в кеше `npx` (`~/.npm/_npx`), сервер запускается как `node <bin>`. При первом запуске, пока пакета в кеше нет, работает через `npx`. Для `@latest` и тегов хаб раз в 12 часов проверяет registry, ставит новую версию в тот же кеш и перезапускает сервер, когда нет текущих вызовов. Выключается переключателем «Run npx packages directly» (`launcher: npx`).
- **HTTP** — Streamable HTTP. OAuth: **Sign in** открывает браузер, ответ приходит на `http://127.0.0.1:33419/callback`. При первом старте подхватываются токены `mcp-remote` из `~/.mcp-auth` для того же URL или хоста.

Серверы стартуют вместе с DSH и работают постоянно. По желанию: остановка после N минут простоя или запуск только при первом вызове. Остановленный или упавший сервер поднимается при следующем вызове. Последний список инструментов хранится на диске, поэтому модель видит инструменты ещё до подключения серверов.

Данные лежат в `<профиль>/mcp-hub/`: `catalog/*.json` — кеш списков инструментов, `oauth/*.json` — токены (права 0600).

## Настройки

Всё настраивается на странице **Plugins → MCP Hub**. Это запись `mcp-hub` в `cordis.patch.yml` профиля, её можно править и руками.

| Поле сервера | По умолчанию | Что делает |
|---|---|---|
| `name` | — | Имя; инструменты называются `mcp__<name>__<tool>` |
| `mode` | `auto` | `eager` / `lazy` / `auto` |
| `transport` | `stdio` | `stdio` или `http` |
| `command`, `args`, `env`, `cwd` | — | Запуск stdio-сервера |
| `url`, `headers` | — | HTTP-сервер |
| `launcher` | `direct` | `direct` — пакеты `npx` без обёртки, `npx` — как есть |
| `idleStopMinutes` | `0` | Остановка после простоя; `0` — работать постоянно |
| `connectAtStartup` | `true` | `false` — брать список инструментов из кеша и запускать при первом вызове |
| `catalog` | `full` | `names` — в каталоге только имена инструментов |
| `instructions` | `auto` | Инструкции сервера в системном промпте: `auto` (у eager), `full`, `off` |
| `description` | — | Строка о сервере в каталоге |
| `toolCallTimeoutMs` | `60000` | Таймаут вызова |

Общие: `autoEagerMaxTokens` (2500), `catalogLineChars` (120), `startupTimeoutMs` (30000), `oauthCallbackPort` (33419).

## API для плагинов

Хаб регистрирует сервис `mcpHub`. Полное описание с типами — [types/mcp-hub.d.ts](types/mcp-hub.d.ts) (экспортируется и как `@opfield/dsh-mcp-hub/types`).

```js
export function apply(ctx) {
  // необязательная зависимость: без хаба плагин просто не подключает серверы
  ctx.inject(['mcpHub'], (scope) => {
    const reg = scope.mcpHub.register(
      { id: 'my-plugin', title: 'My plugin', description: 'Настраиваются в Plugins → My plugin.' },
      [{ name: 'acme', transport: 'http', url: 'https://acme.example/mcp', mode: 'lazy' }],
    )
    return reg // при выгрузке плагина серверы уходят из хаба
  })
}
```

| Метод | Что делает |
|---|---|
| `register(owner, servers)` | Добавляет серверы плагина. Повторный вызов с тем же `owner.id` заменяет список. Возвращает функцию отмены с `update(servers)` и `problems` |
| `servers({ owner })` | Состояние серверов, всех или одного плагина |
| `status(name)` | Состояние одного сервера: статус, инструменты, токены, OAuth и его scopes |
| `action(name, action)` | `restart`, `stop`, `refresh`, `signin`, `signout`, `update` — как кнопки на странице |
| `call(name, tool, args)` | Прямой `tools/call` для нужд самого плагина |
| `onChange(listener)` | Подписка на любые изменения; возвращает отписку |

Правила:

- Имена серверов общие для всего хаба. Серверы пользователя важнее; между плагинами имя остаётся за тем, кто зарегистрировал его раньше. Конфликт и неверные записи не бросают исключение, а попадают в `problems` и показываются на странице хаба.
- `expose: false` оставляет сессию только плагину: модель не видит ни инструментов, ни каталога, ни инструкций сервера.
- OAuth, кеш инструментов, запуск `npx`-пакетов и режимы работают так же, как для серверов пользователя.
- Добавлять, менять и удалять такие серверы может только плагин-владелец. На странице хаба для них доступны вход, перезапуск и список инструментов.
- `version` сервиса — `1`; меняется при несовместимых изменениях.

## Откат

`ELECTRON_RUN_AS_NODE=1 "$DSH" "$HUB/scripts/migrate.mjs" ~/.dsh/profiles/desktop --revert` возвращает старый `cordis.patch.yml`, затем удали плагин в Plugins.

## Разработка

Из корня репозитория:

```sh
npm install
npm test
```

Интеграционные тесты поднимают настоящий stdio MCP-сервер через SDK из `devDependencies`. Чтобы проверить на установленном DSH, задай `DSH_NODE_MODULES=<распакованный app.asar>/dsh/node_modules`.
